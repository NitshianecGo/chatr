# Aurora — мессенджер для своей компании (до ~10 человек)

Красивое современное веб-приложение для переписки: анимации на каждое
сообщение, звуковые эффекты (генерируются прямо в браузере — никаких
mp3-файлов), индикатор "печатает…", статус "в сети", личные и групповые
чаты, отправка фото. Работает в браузере, ставится на GitHub бесплатно.

**Технологии:** React + Vite + Tailwind CSS + Framer Motion (фронтенд,
живёт на GitHub Pages) и Firebase (бесплатный бэкенд Google: логин,
база данных сообщений в реальном времени, хранилище фото).

Своего сервера вам поднимать не нужно — GitHub Pages отдаёт статичный
сайт, а всю "живую" логику (сообщения, онлайн-статусы) делает Firebase.
Для 10 человек это полностью укладывается в бесплатный тариф Firebase
(Spark) — платить не придётся.

---

## Что вам понадобится

- Аккаунт **GitHub** (github.com)
- Аккаунт **Google** — для Firebase (console.firebase.google.com)
- 15–20 минут свободного времени

Устанавливать ничего на компьютер не обязательно — все шаги можно
сделать через браузер. Node.js на компьютере нужен, только если вы
захотите запустить приложение локально для проверки (это необязательно).

## Шаг 1. Создайте репозиторий на GitHub и загрузите файлы

1. Зайдите на github.com → **New repository**.
2. Назовите репозиторий, например `aurora-chat`. Сделайте его **Public**
   (для бесплатного GitHub Pages это проще всего). Кнопку "Add README"
   не нажимайте — у нас уже есть свой.
3. Нажмите **Create repository**.
4. На странице пустого репозитория нажмите **uploading an existing file**
   (или "Add file" → "Upload files").
5. Перетащите **все файлы и папки** из этого проекта в окно загрузки —
   включая скрытую папку `.github` (она отвечает за автосборку) и файл
   `.gitignore`. Если браузер не даёт загрузить папки — используйте
   вариант через Git (ниже) или GitHub Desktop.
6. Внизу нажмите **Commit changes**.

> **Совет:** если умеете пользоваться git — это быстрее:
> ```bash
> git clone <ссылка на ваш пустой репозиторий>
> cd aurora-chat
> # скопируйте сюда все файлы проекта
> git add .
> git commit -m "Aurora chat"
> git push
> ```

## Шаг 2. Создайте проект Firebase

1. Откройте **console.firebase.google.com** и войдите под своим Google-аккаунтом.
2. Нажмите **Add project / Создать проект**. Введите название, например
   `aurora-chat`. На шаге про Google Analytics можно отключить её —
   она не нужна.
3. Когда проект создан, на главном экране проекта нажмите значок
   **`</>`  (Web)**, чтобы зарегистрировать веб-приложение.
4. Введите любое название (например "Aurora Web") и нажмите
   **Register app**. Галочку "Firebase Hosting" ставить не обязательно —
   мы используем GitHub Pages.
5. Firebase покажет блок кода вида:

   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "aurora-chat-xxxxx.firebaseapp.com",
     projectId: "aurora-chat-xxxxx",
     storageBucket: "aurora-chat-xxxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef123456"
   };
   ```

   **Скопируйте эти значения.**

6. В вашем репозитории на GitHub откройте файл **`src/firebase.js`**,
   нажмите на карандаш (Edit), и замените строки-заглушки
   `'ВСТАВЬТЕ_apiKey'`, `'ВСТАВЬТЕ_authDomain'` и т.д. на свои реальные
   значения из пункта 5. Должно получиться примерно так:

   ```js
   const firebaseConfig = {
     apiKey: 'AIzaSy...',
     authDomain: 'aurora-chat-xxxxx.firebaseapp.com',
     projectId: 'aurora-chat-xxxxx',
     storageBucket: 'aurora-chat-xxxxx.appspot.com',
     messagingSenderId: '1234567890',
     appId: '1:1234567890:web:abcdef123456',
   }
   ```

   Сохраните файл (**Commit changes**).

   > Эти значения не секретны — Firebase специально делает их открытыми,
   > это нормально, что они будут видны в исходном коде сайта.
   > Безопасность данных обеспечивают Rules, которые вы настроите в шаге 4.

## Шаг 3. Включите вход по логину и паролю

1. В Firebase Console слева откройте **Build → Authentication**.
2. Нажмите **Get started**.
3. В списке провайдеров выберите **Email/Password**, включите первый
   переключатель ("Email/Password"), нажмите **Save**.

Больше здесь ничего делать не нужно — приложение само создаёт
пользователей, когда кто-то регистрируется по имени и паролю.

---

## Шаг 4. Создайте базу данных Firestore и Storage, вставьте правила безопасности

### 4.1 Firestore (хранит сообщения и чаты)

1. Слева откройте **Build → Firestore Database** → **Create database**.
2. Выберите режим **Production mode** → Next.
3. Выберите ближайший к вам регион (например `eur3` для Европы) → **Enable**.
4. Когда база создана, перейдите на вкладку **Rules** вверху.
5. Удалите всё содержимое и вставьте туда содержимое файла
   **`firestore.rules`** из этого проекта (откройте его на GitHub, скопируйте
   весь текст).
6. Нажмите **Publish**.

### 4.2 Storage (хранит фотографии из чата)

1. Слева откройте **Build → Storage** → **Get started** → next → next → **Done**
   (можно выбрать тот же регион, что и для Firestore).
2. Перейдите на вкладку **Rules**.
3. Удалите содержимое и вставьте текст файла **`storage.rules`** из
   этого проекта.
4. Нажмите **Publish**.

> Если пропустить этот шаг, приложение всё равно заработает, но
> отправка фото и вход/регистрация будут выдавать ошибку
> "Missing or insufficient permissions".

## Шаг 5. Включите GitHub Pages с автосборкой

Проект уже содержит файл `.github/workflows/deploy.yml`, который сам
собирает приложение и публикует его при каждом изменении в ветке `main`.
Нужно только один раз включить Pages:

1. В репозитории на GitHub откройте **Settings → Pages**.
2. В разделе **Build and deployment → Source** выберите
   **GitHub Actions** (не "Deploy from a branch").
3. Откройте вкладку **Actions** в репозитории. Если сборка ещё не
   запустилась сама — откройте workflow **"Deploy to GitHub Pages"**
   и нажмите **Run workflow**.
4. Дождитесь, пока обе стадии (**build** и **deploy**) станут зелёными
   — обычно это занимает 1–2 минуты.
5. Снова зайдите в **Settings → Pages** — там появится ссылка вида
   `https://ваш-логин.github.io/aurora-chat/`. Это и есть адрес вашего
   мессенджера.

---

## Шаг 6. Позовите друзей

Просто отправьте всем ссылку на сайт. Каждый заходит и жмёт
**"Нет аккаунта? Зарегистрироваться"**, придумывает имя пользователя и
пароль. После этого все видят друг друга в списке при создании нового
чата (кнопка **"+"** в левой панели) — можно писать лично или создать
групповой чат.

## Проверка на своём компьютере (необязательно)

Если у вас установлен Node.js (18+), можно запустить приложение локально
до публикации, чтобы всё проверить:

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173`. Изменения в коде видно
сразу, без пересборки.

Собрать финальную версию вручную (то же самое делает GitHub Actions
автоматически):

```bash
npm run build
npm run preview
```

## Структура проекта

```
src/
  firebase.js            ← сюда вставляется конфиг Firebase (Шаг 2)
  contexts/AuthContext.jsx  ← логика регистрации/входа/выхода
  lib/chatApi.js          ← отправка сообщений, создание чатов
  components/
    AuthScreen.jsx         ← экран входа
    Sidebar.jsx             ← список чатов слева
    ChatWindow.jsx          ← окно переписки
    MessageBubble.jsx       ← одно сообщение
    NewChatModal.jsx        ← окно "новый чат / новая группа"
    AuroraBackground.jsx    ← анимированный фон
  hooks/useSound.js         ← звуки, генерируются кодом (без файлов)
firestore.rules            ← вставить в Firebase Console (Шаг 4.1)
storage.rules               ← вставить в Firebase Console (Шаг 4.2)
.github/workflows/deploy.yml ← автосборка и публикация на GitHub Pages
```

### Как поменять оформление

- Цвета — файл `tailwind.config.js`, раздел `colors` и `backgroundImage.aurora`.
- Шрифты — подключены в `index.html` (Google Fonts: Space Grotesk / Inter),
  используются через классы `font-display` / `font-body`.
- Звуки — файл `src/hooks/useSound.js`, можно менять частоты и длительность
  нот в функции `tone(...)`.

## Возможные проблемы

**Белый экран после публикации.**
Откройте сайт, нажмите F12 (консоль разработчика) и посмотрите на
ошибку. Почти всегда это означает, что в `src/firebase.js` остались
незаполненные строки `'ВСТАВЬТЕ_...'` — вернитесь к Шагу 2.

**"Missing or insufficient permissions" при регистрации/сообщениях.**
Значит, правила Firestore/Storage не опубликованы — повторите Шаг 4 и
не забудьте нажать **Publish**.

**Сборка (Actions) падает с ошибкой.**
Откройте вкладку **Actions** → нажмите на неудачный запуск → посмотрите
лог. Чаще всего причина — файл `src/firebase.js` был случайно испорчен
при редактировании (например, потеряна кавычка). Откройте файл и
сверьте со структурой из Шага 2.

**Не приходят звуки.**
Браузеры разрешают звук только после того, как пользователь хоть раз
кликнул на странице (это защита от автозвука на сайтах, не ошибка
приложения) — первый клик по чату включит звук для всех следующих
сообщений.

**Лимиты бесплатного тарифа Firebase.**
Spark-тариф даёт, например, 50 000 чтений и 20 000 записей в Firestore
в день — для 10 активных пользователей этого достаточно с большим
запасом. Если однажды понадобится больше — Firebase предложит перейти
на платный тариф Blaze прямо в консоли.
